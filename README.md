# AI-Powered Stock Analysis & Momentum Investment Platform

An end-to-end demo combining a momentum ranking engine, LLM-based news
sentiment analysis, and a paper (simulated) trading engine, wired together
behind a FastAPI backend.

## Project layout

```
ai_stock_platform/
├── momentum/
│   └── momentum_engine.py       # ranks stocks by trailing price momentum
├── news_sentiment/
│   ├── news_sentiment_scraper.py  # pulls RSS news, classifies sentiment via Claude
│   └── company_tickers.csv        # company name -> ticker lookup
├── paper_trading/
│   ├── paper_trading_engine.py    # simulated portfolio: allocation, tracking, P/L
│   └── paper_trading.db           # SQLite database (created on first run)
├── api/
│   └── main.py                    # FastAPI app wiring the three engines together
├── requirements.txt
└── README.md
```

## Setup

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY="your-key-here"   # needed for news sentiment only
```

## Running each piece standalone

**Momentum rankings:**
```bash
python momentum/momentum_engine.py
# or with a custom ticker list:
python momentum/momentum_engine.py AAPL MSFT NVDA TSLA
```

**News sentiment:**
```bash
python news_sentiment/news_sentiment_scraper.py
```

**Paper trading demo:**
```bash
cd paper_trading
python -c "
from paper_trading_engine import PaperTradingEngine, RiskRules
engine = PaperTradingEngine('paper_trading.db')
pid = engine.create_portfolio('Demo', 1000)
print(engine.get_portfolio_summary(pid))
"
```

## Running the full backend

```bash
uvicorn api.main:app --reload
```

Then open `http://localhost:8000/docs` for interactive API documentation
(auto-generated by FastAPI), or hit endpoints directly:

```bash
# Get top 10 momentum stocks
curl http://localhost:8000/momentum?top=10

# Create a portfolio
curl -X POST http://localhost:8000/portfolio \
  -H "Content-Type: application/json" \
  -d '{"name": "My Portfolio", "starting_capital": 1000}'

# Build it from the current momentum ranking
curl -X POST http://localhost:8000/portfolio/1/build \
  -H "Content-Type: application/json" \
  -d '{"max_positions": 5}'

# Check the portfolio
curl http://localhost:8000/portfolio/1
```

## Known limitations / next steps

- **Momentum engine** uses yfinance (free, no key, but not production-grade —
  swap for Finnhub or Polygon.io if you need reliability at scale or
  intraday data).
- **News sentiment** currently classifies every matched article on every run
  with no caching — add a "seen article" cache (by URL) before running this
  on a schedule, or you'll pay for re-classifying the same headlines.
- **Paper trading allocation** is equal-weight within risk caps and only
  buys whole shares — with small starting capital and high-priced stocks,
  this can under-deploy capital (fewer positions than `max_positions`).
  A second allocation pass that redistributes leftover budget to
  affordable candidates would fix this.
- **No database migrations** — the SQLite schema is created via
  `CREATE TABLE IF NOT EXISTS` on startup; moving to Postgres/cloud DB will
  need a proper migration tool (Alembic, etc.).
- **No authentication** — the API has no user accounts or auth; every
  portfolio is globally accessible by ID. Fine for a demo/capstone, not for
  production.
- **No scheduled jobs yet** — momentum and news updates only run when you
  call the endpoints. Cloud deployment should add a scheduler (cron, Azure
  Functions Timer Trigger, AWS EventBridge, etc.) to refresh data
  automatically.
